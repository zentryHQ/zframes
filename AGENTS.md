# zframes

AI-personalizable market dashboard framework (working name — do NOT call it "hyperframes"; that's HeyGen's project, which we use as the distribution-model reference). An agent reads the frame catalogue (Zod → JSON Schema), emits a `dashboard.json` spec, and the runtime validates + renders it as a live dashboard.

## Commands

```bash
pnpm install
pnpm dev          # runtime at http://localhost:37263 (project default port, strict)
pnpm typecheck    # tsc --noEmit across all workspace packages (pnpm -r)
pnpm build        # vite build of the runtime
pnpm build:cli    # build the zframes CLI + its prebuilt runtime bundle
pnpm zframes serve <dashboard.json>   # the runtime: serve a dashboard live (--port to change)
pnpm --filter @zframes/storybook dev  # Storybook — every frame in all variants/states at :6006
pnpm test:providers      # LIVE smoke: hit every keyless provider's real API, assert the response shape
pnpm test:frames:render  # headless-render every frame in a built Storybook, flag error cards / crashes
```

`pnpm test` is hermetic (stubs fetch) and gates every PR. Alongside it, a **scheduled-monitor suite** runs on crons and files GitHub issues instead of gating PRs: provider liveness, published-CLI smoke (linux/macos/windows), frame-render, and a `pnpm audit` (+ Dependabot). See `.github/scripts/README.md`. **Releasing the CLI:** bump `packages/cli/package.json` version, commit, then `git tag v<version> && git push origin v<version>` — `release.yml` verifies, builds, and npm-publishes via trusted publishing (OIDC + provenance; no token). CodeQL (default setup) and secret-scanning push protection run repo-side.

## Structure

> **Package topology (core-split 2026-07-01; facade retired 2026-07-03).** `@zframes/core` was decomposed into bounded-context packages; the transitional back-compat facade shims are gone — every consumer imports the leaf packages directly, and `@zframes/core`'s only subpath is its root barrel (which still re-exports the spec kernel for frame/app consumers). Where the code lives:
> - `@zframes/spec` — domain kernel (React- and Node-free): `types`, `DashboardSpecSchema` (`spec`), `routes`, `frame`/registry, `presets`, `catalogue`.
> - `@zframes/data-primitives` — the `fetch` + `cache` transport primitives plus `csv` row parsing (React-free).
> - `@zframes/store` — the XDG global store (Node, zero-dep leaf).
> - `@zframes/zai` — the agent-orb harness (`agent`, Node). Spawns the user's local CLI (`claude -p`/`codex exec`) inheriting the server env; `ZFRAMES_CLAUDE_CONFIG_DIR` / `ZFRAMES_CODEX_HOME` point **only** zframes's child at a specific account (config/creds dir) — safe to export globally, never hijacks a bare `claude`/`codex` (`resolveAgentEnv`).
> - `@zframes/account` — keyed-account HMAC relay + credentials (Node).
> - `@zframes/serve` — spec read/write + official-data proxy (Node).
> - `@zframes/vite` — the `dashboardWriteback()` dev plugin (Node; composes serve/zai/account/store).
> - `@zframes/editor` — the `DashboardEditor` authoring UI (React + GridStack).
> - `@zframes/unicorn` — the shared Unicorn Studio scene loader (`UnicornScene`) + the `useLowEndDevice`/`useReducedMotion` backdrop gates (React, generic leaf — no @zframes imports; both hosts compose it).
> - `@zframes/core` — the presentation layer (`DashboardRenderer`, `frame-content`, capability hooks, `visibility`); its root barrel also re-exports the spec kernel.
>
> ESLint `no-restricted-imports` enforces the layer DAG (spec ← core ← editor; providers import spec + data-primitives only; Node infra imports no React/presentation); `tests/dep-dag.test.ts` pins the same DAG at the package.json level, and `packages/core/src/barrel-surface.test.ts` snapshot-pins the public core barrel. Node-loaded files (serve/vite/account/agent) import siblings by **package subpath**, never relative.
>
> **Where new code goes** (always import the leaf package):
> - New spec field / frame-meta shape / theme preset / catalogue change → `packages/spec` (then the `--zf-*` mapping in core's `frame-content.tsx`/`renderer.tsx` and the editor rail if it's cosmetic).
> - Transport, caching or delimited-response parsing (fetch, proxy rewrite, TTL/dedup/persist, CSV rows) → `packages/data-primitives`.
> - New capability hook / renderer chrome → `packages/core` (`hooks.tsx` / `frame-content.tsx`).
> - Authoring-UI behaviour (palette, rail, grid interactions, default-config seeding) → `packages/editor`.
> - Spec read/write or proxy route → `packages/serve`; new proxied provider host → its allowlist in `serve.ts`.
> - Store/dashboard-resolution behaviour → `packages/store`; credentials/relay → `packages/account`; orb/harness → `packages/zai`; dev-plugin composition only (no logic) → `packages/vite`.
> - New frame → `packages/frames` (four lists, see `packages/frames/AGENTS.md`); new provider → a new `packages/provider-*` + wiring in the composition roots (`apps/runtime/src/App.tsx`, explorer).

- `packages/core` — `defineFrame`/`defineFrameMeta`, registry, `DashboardSpecSchema`, `DashboardRenderer` (CSS-grid; error cards for invalid config AND missing capabilities), capability-routed multi-provider hooks, `catalogueForAI`. The card/error/chrome rendering both renderers share lives in `frame-content.tsx` (`FrameContent` + `FRAME_CSS`). Spec extras: `background` (`BackgroundSchema`) on the dashboard, **per-card event markers** (`FrameInstance.events`: `EventMarkerSchema[]` — hand-authored `{date,label,note?,color?,url?}` annotations drawn on THAT card's time axis, resolved by `FrameEventsProvider` → `useEvents()`; only frames whose meta sets `annotatable` draw them; see Conventions), **nested frame groups** (`FrameInstance.children`: `ChildFrameInstanceSchema[]` — the frames a *container* frame holds, rendered as its own little grid so a cluster takes one board slot and moves/resizes as a unit; see Conventions), plus four dashboard-wide cosmetic groups split by fault line — `grid` (geometry: columns/rowHeight/gap), `theme` (`ThemeSchema`: colour — accentHue + accentSat for the accent, baseHue + baseSat for the dark card-surface tint, upColor + downColor for the semantic gain/loss hex pair routed through `--zf-up`/`--zf-down`), `typography` (`TypographySchema`: fontFamily sans/mono/serif + numericStyle proportional/tabular + scale global text size, applied as the host root font-size) and `appearance` (`AppearanceSchema`: card-surface radius/borderStrength/surfaceOpacity/density/elevation), each field mapped to a `--zf-*` var read by `FRAME_CSS` (the base-surface gradient is expressed off `--zf-base-hue`/`--zf-base-sat` with lightness baked, and the family routes through the `--font-dmsans` token, so the defaults reproduce the original look to within ~1/255). Named one-click looks live in `presets.ts` (`THEME_PRESETS`, exported from `@zframes/core`) — pure data the editor's Cosmetics rail and the agent can apply, never a separate render path. Every default is a visual no-op, and a legacy `grid.radius` auto-migrates into `appearance` via a spec `preprocess`. Frame meta carries a required `category` (one of `FRAME_CATEGORIES`, an ordered `{key,label,description}` taxonomy exported from `@zframes/core` — it groups the editor palette into labelled sections and is surfaced in `catalogueForAI` so the generating agent reasons by family), optional `chrome: "bare"` (renders chrome-less — headings become zone dividers) and optional `layout` (`{w,h,minW?,minH?,maxW?,maxH?}` — editor sizing only, ignored by the CSS-grid renderer). Deep exports (`@zframes/spec/spec`, `/frame`, `/catalogue`) are React-free for tooling. Opt-in subpaths back the editable dashboard + the runtime: `@zframes/editor/editor` (`DashboardEditor` — see Conventions), `@zframes/serve` (Node-only `handleSpecRead`/`handleSpecWrite` + `handleProxy` — the spec read/write contract AND a host-allowlisted same-origin official-data proxy at `/__zframes/proxy`, all shared by the dev plugin and the CLI), `@zframes/store` (Node-only global-store layer — the XDG config home, the path-vs-name `classifyTarget`, the global-default-first `resolveServeTarget`, and `list`/`getDefault`/`setDefault`; the CLI commands + the keyed-account credential path all read the one home from here), and `@zframes/vite` (`dashboardWriteback()` dev plugin, which also serves the spec for the app to fetch). Provider primitives, React-free and used by every provider: `@zframes/data-primitives/fetch` (the shared transport — UA, proxy rewrite, abort, optional Zod validation), `@zframes/data-primitives/cache` (`TtlCache` — the shared TTL + in-flight-dedup + stale-on-error + opt-in-persist cache; see the caching convention below) and `@zframes/data-primitives/csv` (`splitCsvRow`/`parseCsvRows` — quote-aware row parsing for the CSV-published official sources; a bare `split(",")` is silently wrong on any file whose rows quote a comma, e.g. Zillow's `"Austin, TX"`, and shifts every later column by one). **Official-data proxy:** browsers can't fetch CORS-blocked official sources (SEC XBRL, H.15, OFR, halts), so a provider passes `fetchJson(url, schema, { proxied: true })` — in the browser this rewrites to the same-origin `/__zframes/proxy?url=…` route (Node relays it; allowlisted hosts only, https/GET-only, browser UA or `--contact`/`ZFRAMES_CONTACT`); in Node it's a no-op (no CORS there). Proxied frames degrade to empty on a static host with no runtime. See the proxy decision in `docs/decisions/providers/providers.md`.
- `packages/charts` — D3 base chart layer ported from zTerminal (`tree-chart`, `heatmap-chart`, `multi-series-line-chart`, `stacked-area-chart`, `pie-chart`, `mini-line-chart`) plus in-house additions (`bar-chart` — vertical/horizontal, diverging-aware; `scatter-chart` — x/y bubble, linear/log y; `radial-gauge` — bounded-scalar arc with a center slot) and `theme.css` (zTerminal design tokens for Tailwind v4). `multi-series-line-chart` also takes an optional `events: ChartEvent[]` and overlays an `EventLayer` (dashed rule + top flag + hover/focus tooltip, neighbours within 18px clustered, out-of-window markers dropped) — generic annotations the caller supplies (in practice the card's own), not a data source. Implementation-agnostic: no business logic, no data fetching.
- **Crypto market data (keyless):**
  - `packages/provider-hyperliquid` — free no-key provider: allMids WS (one subscription per HIP-3 dex, added lazily from requested symbols), day stats per dex (full default-dex universe when no symbols given; a `"<dex>:*"` wildcard symbol — e.g. `"xyz:*"` — returns that dex's *entire* universe, used by the ticker tape to surface every HIP-3 equity), fundingHistory, candleSnapshot, open interest (`open-interest` capability — live single-venue notional, read from the same `metaAndAssetCtxs` call as day stats; no history endpoint)
  - `packages/provider-coingecko` — global marketcap + dominance (`global-market`), per-coin market caps (`coin-markets`, top-50 by mcap with 24h change), trending coins (`trending-coins`), sector performance (`sector-performance`), and blue-chip NFT collections (`nft-market` — floor/24h-change/volume/sales for ~10 curated slugs, fetched **sequentially** one `/nfts/{id}` call at a time with per-collection skip-on-fail and a long 45 m TTL, since the keyless tier has no bulk NFT endpoint and shares this provider's rate limit); free tier no key, all endpoints cached behind `TtlCache` (stale-on-429)
  - `packages/provider-coinpaprika` — broad multi-window coin movers across ~2000 coins (`coin-movers` capability)
  - `packages/provider-alternativeme` — fear & greed index (`sentiment` capability)
- **On-chain / DeFi (keyless):**
  - `packages/provider-defillama` — keyless via api.llama.fi (CORS-open): TVL per chain (`tvl`), DEX volume (`dex-volume`, snapshot + per-protocol history), protocol TVL (`protocol-tvl`, snapshot + per-protocol history), protocol fees (`protocol-fees`). Snapshots/histories cached behind `@zframes/data-primitives/cache`'s `TtlCache`
  - `packages/provider-mempool` — Bitcoin fees, mempool, blocks, hashrate, difficulty, mining pools, and Lightning stats (keyless, mempool.space)
  - `packages/provider-geckoterminal` — trending/hot DEX pools per network (`dex-pools`) via GeckoTerminal's keyless public API (~30 req/min): pair, base-token price, 24h volume/change, liquidity, trade count; keyed by network (eth/solana/base/…), short TTL (not persisted — hot pools are too short-lived)
  - `packages/provider-blockchair` — cross-chain network activity (`chain-activity`) for major L1s (Bitcoin, Ethereum, Litecoin, Dogecoin, …) via Blockchair's keyless `/{chain}/stats`: 24h tx count, blocks, mempool size, native price + 24h change; per-chain calls fan out in parallel with skip-on-fail, aggregate cached 4 m
- **Non-USD source (keyless):**
  - `packages/provider-bitkub` — Bitkub, Thailand's largest exchange and where KUB actually trades. Fulfils the SAME capabilities the other sources do (`day-stats`, `ohlcv`, plus `order-book`, which no other provider has), so **existing** frames render it — a frame reaches it by pinning `source: "bitkub"` in its config, since capability routing is otherwise first-match. Bitkub quotes in THB but every capability is denominated in USD, so prices are converted on the way out at the live USD/THB rate (fetched by the provider itself — the layer DAG forbids importing `provider-fx` — through its own copy of the same four-source chain, 1 h TTL, persisted); sizes/volumes in the base asset are NOT converted. **Every rate is sanity-checked before dividing by it** (`10 ≤ USD/THB ≤ 100`, falling through to the next source otherwise), because a wrong-but-finite rate corrupts every price here more quietly than an outage does; when the whole chain is down a stale cached rate is served rather than throwing. **Footgun:** v1 and v3 spell pairs differently and are not interchangeable — v1's ticker map keys are quote-first (`THB_KUB`), while v3/chart endpoints want base-first (`KUB_THB`), and `/api/market/depth?sym=THB_KUB` answers HTTP 200 with a *different pair's* book instead of an error. The chart endpoint also rejects TradingView's `countback`, so the candle window is anchored to `Date.now()` per call.
- **Derivatives / options (keyless):**
  - `packages/provider-deribit` — BTC/ETH put-call ratio, OI-by-strike, DVOL volatility index (Deribit public API, no key)
- **FX (keyless):**
  - `packages/provider-fx` — foreign-exchange reference rates with a short trend (`fx-rates` + `dollar-index` capabilities), resolved through an **ordered chain of four keyless CORS-open upstreams** (`sources.ts`): Frankfurter/ECB (primary — the healthy path still makes exactly one request) → FXRatesAPI → currency-api (pages.dev, CC0) → ECB Data Portal direct (SDMX). Each adapter normalizes into one internal `RateTable`, so the chain is invisible to callers; when all four fail the **primary's** error is re-thrown. A 429 both falls through **and** cools that source down for 10 min. Opt-in `{ intraday: true }` attaches FXRatesAPI's minute quote as `spot`/`spotAt` and deliberately leaves `rate`/`history`/`changePct` on the published daily close — the board's conversion rate must not flap between polls. History depth is per-call (`{ windowDays }`, default `FX_DEFAULT_WINDOW_DAYS = 40`; the deep sources reach 1999) and is part of the cache key. **Footgun:** FXRatesAPI serves timeseries **newest-first**, and the ECB portal sends `structure.dimensions` (plural), not the documented `dimension`.
- **Metals / commodities (keyless):**
  - `packages/provider-metals` — gold, silver, platinum, palladium and copper from four keyless sources: live spot via gold-api.com (`metal-spot`), the LBMA's own daily London fix files back to **1968** (`metal-history` — the deepest price history in the fleet; ~150 KB gzipped per metal, so its `TtlCache` is 6h and deliberately **not** persisted), the CFTC's public Socrata Commitments-of-Traders dataset (`metal-positioning`, weekly), the U.S. Treasury's monthly official gold-reserve report (`gold-reserve`, the one proxied call — fiscaldata is already allowlisted), and gold-backed tokens via CoinGecko (`tokenized-gold`, premium vs spot). Spot change is measured against the latest London fix: the history warm-up is fire-and-forget, so the change appears a poll after the price rather than blocking first paint on a decades-deep download.
- **Official US macro & financial data (keyless, same-origin proxy required — these degrade to empty on a static host):**
  - `packages/provider-treasury` — U.S. Treasury data: average interest rates, debt-to-penny, completed auctions, and the daily yield curve (fiscaldata + home.treasury.gov, both proxied)
  - `packages/provider-nyfed` — New York Fed reference rates (SOFR, EFFR, repo)
  - `packages/provider-ofr` — OFR Financial Stress Index (`financial-stress` capability)
  - `packages/provider-bls` — BLS public time series (CPI, unemployment, etc.)
  - `packages/provider-finra` — FINRA daily reported short-sale volume (`short-volume`; cdn.finra.org is CORS-blocked in the browser, so it routes through the proxy)
  - `packages/provider-sec` — SEC EDGAR company filings (submissions endpoint is CORS-safe; the companyfacts/XBRL blob routes through the proxy)
  - `packages/provider-news` — news-outlet headlines via RSS (`news` capability)
  - `packages/provider-fred` — FRED (St. Louis Fed) published series, ONE provider parameterised by series id (the provider-metals pattern) across four capabilities: `index-level` (SP500 / VIXCLS / NASDAQCOM), `credit-spread` (the ICE BofA high-yield + investment-grade OAS pair), `housing-price` (Case-Shiller national) and `mortgage-rate` (the Freddie Mac 30y benchmark, which FRED mirrors — so no separate PMMS provider). **Keyless because it reads `fredgraph.csv?id=…`** — the endpoint FRED's own charts download — not the key-gated `api.stlouisfed.org`. Two footguns: `id=A,B` fetches several series in **one** call on a shared date grid (how the spread pair stays aligned by construction), and FRED's **licensed series carry a rolling window** — `SP500` is ~10 years and the BAML spreads ~3, while NASDAQCOM/MORTGAGE30US (1971) and CSUSHPINSA (1987) are deep, so a 20-year request on the S&P returns the 10 that exist.
  - `packages/provider-fhfa` — FHFA House Price Index at **state and metro** granularity, quarterly back to 1975 (`regional-housing-price`) — the sub-national counterpart to FRED's single national series. **Footgun cluster, all confirmed live:** the combined `hpi_master.csv` is ~17 MB, *over* `PROXY_MAX_BYTES`, so it relays as a 502 "upstream response too large" while `curl` looks fine — this reads the small per-level files instead (`hpi_at_state.csv` ~190 KB, `hpi_at_metro.csv` ~4 MB); filenames are **lowercase** (`HPI_master.csv` 404s); the `hpi_po_*.csv` "purchase-only" files are actually **XLSX** behind a `.csv` name; the files have **no header row** and their column order DIFFERS by level; and the metro change column uses undocumented accounting parentheses (`( 3.62)`), so year-over-year is computed from the index instead. Metro keys are full CBSA titles, so a leading fragment resolves case-insensitively ("Austin" → "Austin-Round Rock-San Marcos, TX").
- **Housing (keyless, NO proxy — CORS-open):**
  - `packages/provider-zillow` — the Zillow Home Value Index (`home-value-index`): the typical home value per US metro in **dollars**, not index points, monthly back to 2000. The only house-price source in the fleet denominated in money, so it answers "what would a house cost there" rather than "how much have prices risen" — and therefore the only one that goes through `useMoney()` while the index series stay unit-less. `files.zillowstatic.com` sends `Access-Control-Allow-Origin: *`, so it fetches direct and keeps working on a static host. One wide table (~895 rows × ~318 month columns, ~4.4 MB), so the cache holds the parsed **table** under a constant key and slices per request — a board with three ZHVI cards costs one download, not three.
- **Keyed / account tier (opt-in, not in the published keyless CLI by default):**
  - `packages/provider-binance` — connected Binance account (`portfolio` capability); secret never reaches the browser — routed through the runtime's server-side signed relay
  - `packages/provider-wallet` — public on-chain wallet address (`portfolio` capability); Ethereum balances via public RPC + bundled token list, priced through CoinGecko; no key, no relay
- `packages/frames` — the frames, grouped into the `FRAME_CATEGORIES` families. **`src/schemas.ts` is the metadata source of truth** — pure Zod, no React, imported by both the components and the CLI. Adding a frame touches four lists a `registry-parity.test.ts` keeps in lockstep — meta in `schemas.ts` (→ `allFrameMetas`, plus `frameMetas` if agent-pickable), a component `.tsx`, and entries in `allFrames` **and** `lazy.ts` (a missing `lazy.ts` loader renders as a silent "Unknown frame" card); see `packages/frames/AGENTS.md`. No Storybook edit needed — a Default/AllVariants/States story auto-generates per frame. For the live, grouped frame list (which family holds which frames), read it from the source — the editor palette or `catalogueForAI` (`@zframes/core`), both driven off `FRAME_CATEGORIES` + the registry — rather than a hand-kept list here.
  The package also re-exports `AssetLogo`/`assetLogoUrl`/`tickerOf` (keyless CDN logos + HIP-3 prefix stripping) for hosts.
- `packages/cli` — `zframes init | serve | list | use | catalogue | lint | snapshot` (tsup-bundled bin that ALSO ships a **prebuilt runtime bundle** — a `vite build` of `apps/runtime` vendored by `scripts/build-runtime.mjs` on `pnpm build:cli`, gitignored under `runtime/`). **Global store:** dashboards live in `$XDG_CONFIG_HOME/zframes` (default `~/.config/zframes`) — one **folder per dashboard** (`dashboards/<name>/dashboard.json` + its own siblings: the `daily-analysis.json` brief, local images), plus a root `config.json` (`{default}`) and `credentials.json` (machine-scoped, never inside a dashboard folder) — so the CLI runs from anywhere, holds many, and each dashboard's assets stay isolated. (Legacy flat `dashboards/<name>.json` still resolves on read via `findDashboardFile`.) A bare token (`crypto`) is a store **name**; any arg with a `/` or a `.json` suffix is a **path** (fully back-compat). The path/name resolver (`classifyTarget`), store ops, and the global-default-first `serve` resolution (`resolveServeTarget`) all live in `@zframes/store` (Node-only). `init` writes a bare, schema-valid `dashboard.json` (the fixed package.json-style envelope — `version` semver string, `title`, `author`, then `grid` geometry, unicorn `background`, accent `theme`, card-surface `appearance`, empty `frames`) so the agent fills only `frames`, never hand-authoring boilerplate; a bare-name `init` lands in the store and becomes the default if none is set yet (`--default` to force; `--title`/`--author`; refuses to clobber unless `--force`); `serve` is the runtime (node:http on 127.0.0.1:37263 serving the bundle + the dashboard + a writeback PUT) and with no arg resolves **global-default-first** (config default → cwd `./dashboard.json` → sole store entry); `list`/`use` show/set the default; `lint` is the generating agent's feedback loop; `snapshot` feeds /zframes-brief (resolves global-default-first like `serve` — a bare `snapshot` briefs the default — and emits a `dashboard` block with the per-dashboard `logPath`, so each store dashboard keeps its OWN brief at `dashboards/<name>/daily-analysis.json` served at the frame's default `/daily-analysis.json` out of that folder, never one shared log; a plain-path target keeps the legacy `public/daily-analysis.json`). **In-app dashboard switcher:** when `serve` hosts a *store* dashboard it answers `/__zframes/dashboards` (GET list) + `/__zframes/switch` (POST re-points the mutable current-file pointer the read/write/ask routes follow), and the runtime header opens an on-demand card chooser to switch + reload (the default still always opens first) — CLI-only (absent under `vite dev`; an explicit-path serve reports `canSwitch:false`, where switching stays off). Keyed-account credentials also moved to the XDG home (`credentials.json`, in the `0700` store home). **The CLI is the only published artifact** (the `@zframes/*` packages stay `private`, inlined via tsup `noExternal`).
- `skills/zframes/SKILL.md` — the agent skill: resolve CLI (`npx zframes`) → `init <name>` a bare `dashboard.json` into the global store (or a path) → read catalogue → interview → fill `frames` → lint → `zframes serve <name>` (npx-only; no scaffold).
- `apps/runtime` — the Vite app that IS the runtime. `App.tsx` **fetches** its spec at runtime from `/__zframes/dashboard.json` (served by the dev plugin under `pnpm dev`, by `zframes serve` in prod) and renders it through `DashboardEditor` (not the bare `DashboardRenderer`), so it's end-user-editable; `onSave` PUTs the edited spec to `/__zframes/dashboard` and reloads. Tailwind v4 via `@tailwindcss/vite` (`@source` scans workspace packages). `pnpm build:cli` `vite build`s this app into the CLI's `runtime/`. Renders `spec.background` via `src/background.tsx` (Unicorn Studio scene through the shared `@zframes/unicorn` loader, lazy-loaded, behind a contrast scrim). Renders a pinned live ticker tape via `src/ticker-tape.tsx` (`TickerTape`) — **host chrome, not a frame**: always-on, fixed to the viewport bottom, outside the editable grid, never declared in the spec. The header carries a `src/dashboard-chooser.tsx` (`DashboardChooser`) — also host chrome: it GETs `/__zframes/dashboards`, and when `serve` reports `canSwitch` with >1 store dashboard it turns the title into a button opening a card-overlay chooser; picking a card POSTs `/__zframes/switch` then reloads. Otherwise (dev, explicit-path serve, single dashboard) it falls back to the static title. `serve` always opens the default dashboard — the chooser is on-demand, never a forced landing. It runs inside `<FramesProvider>` (shares the app's providers, no extra WS), surfaces stocks first (`getDayStats(["xyz:*"])`) then the crypto universe (`getDayStats()`), each with a logo + live mid + 24h change, in a CSS marquee.
- `apps/storybook` — a Storybook (port 6006) that renders **every frame in isolation, across all variants and states**, for fast visual testing. It feeds a one-frame `DashboardSpec` to the real `DashboardRenderer` (so chrome, `--zf-*` theme vars, and the error/loading paths match production) wrapped in `FramesProvider` with a deterministic, **offline** `MockMarketDataProvider` (`src/mock-provider.ts`) instead of live data — the provider advertises every capability and has four modes (`normal`/`loading`/`empty`/`error`); **no provider packages are imported**. `scripts/gen-stories.ts` generates one `src/stories/<frame>.stories.tsx` per frame on `predev`/`prebuild` (enumerated from the React-free `@zframes/frames/schemas` so it covers the **full** set, not the curated `frameMetas` subset). Each frame gets three stories: **Default** (Controls auto-derived from its Zod schema), **AllVariants** (every enum/boolean/curated config in a grid), and **States** (the four provider modes). A toolbar switches **theme preset / frame size / density** globally. Curated bases/variants live in `src/curated.ts`; the universal config seed reuses the editor's `buildDefaultConfig` via the `@zframes/editor/editor-symbols` subpath. Generated `src/stories/` and `storybook-static/` are gitignored.
- `patches/liveline@0.0.7.patch` — vendored from zhive (DPR fix + label precision); applied via pnpm `patchedDependencies`

## Conventions

- pnpm only. Packages ship TypeScript source (`main: src/index.ts`); the runtime's Vite consumes them directly (`optimizeDeps.exclude`).
- Every frame schema field needs `.describe()` — schemas are read by generating agents via `catalogueForAI`.
- `dashboard.json` is the AI-generated artifact. Invalid frame configs render as per-frame error cards (the agent's feedback loop), never crash the dashboard.
- Frame chrome (cards, titles, hover) lives in the renderer's injected `.zf-*` stylesheet, themeable via `--zf-*` CSS vars — frames style only their interior.
- Dashboard background: the **spec declares** it (`background: {type: "gradient"|"unicorn"|"none", projectId?, opacity?}`), the **host renders** it (runtime's `background.tsx`) — same split as providers. Scene `opacity` is kept moderate (~0.15) so it reads as a living backdrop in the gutters, not a distraction; cards are opaque so content always wins. The Unicorn Studio engine lives only in the hosts, never in core — loaded by the shared in-house loader (`@zframes/unicorn`, used by both the runtime background and the explorer front door), NOT the `unicornstudio-react` npm package (which inlines a ~1.3 MB copy of the engine into the bundle even when you load it from a URL, as we do). **Footgun:** a `unicorn` background injects the self-hosted engine (`apps/runtime/public/unicornStudio.umd.mjs`, shipped in the prebuilt bundle — not a CDN) and fetches the scene from a hosted Unicorn Studio project (Aurora, `SCENE_DEFAULT_PROJECT_ID` in `@zframes/spec`, is the zframes default) — keyless, but the scene fetch is still an external runtime dependency; it falls back to the body gradient if the engine or scene fails to load. The skill emits `unicorn` by default.
- Original assets only. Deliberate exceptions (all Zentry's own IP; public release pends owner sign-off): `packages/charts` (port of zTerminal) and `packages/frames/src/use-countdown.ts` (port of zhive's `useCountdown` — the optimized global-tick/viewport-gated readout that drives the `clock` frame).
- Base charts stay generic — no business logic, no data fetching; frames own data, charts own rendering.
- **Display currency is a display-layer concern, never a provider one.** Every capability is denominated in **USD** — a provider on a non-USD source converts on the way out (see `provider-bitkub`). The dashboard declares `currency: { code }` (`CurrencySchema`, **146 codes**) and a single card can override it with `FrameInstance.currency` — note the two are **different shapes**: the board field is an object (`currency: { code: "THB" }`) while the per-card override is a **bare code string** (`currency: "USD"`, a sibling of `config`). Both are settable from the editor: a searchable `CurrencyPicker` (`packages/editor/src/currency-picker.tsx`, matching on code + symbol + `Intl.DisplayNames` name, majors pinned first since 146 codes sorted alphabetically would open on AED) backs the Cosmetics rail's Currency section and a per-card "Display currency" field in the frame config rail. Picking **"Inherit board"** *deletes* the key rather than writing a value equal to the board's — a card pinned to `USD` stops following the board, so inherit and pin are genuinely different documents. the list is **derived, not hand-typed** — a code ships only if **at least two** of `provider-fx`'s four chain sources quote it, so every board currency inherits the chain's fallback rather than resting on one upstream. Deliberately excluded: single-source fiat (VES, ZWG, SLE, MRU, STN, XCG, CNH — one quoting source each), metals (XAU/XAG/XPT/XPD are *units*, not currencies), crypto, funds codes (XDR), and codes `Intl` still carries but ISO-4217 withdrew (HRK, CUC, SLL, ZWL, ANG). A weekly monitor (`.github/scripts/fx-coverage.mjs`) re-derives the ≥2-source set from live coverage and files an issue when a shipped code loses its fallback — and deliberately **skips the diff entirely** when any source is unreachable, since recomputing from the survivors would report half the enum as regressed. **Footgun:** the metals exclusion must never be a blanket `X*` filter — XAF/XOF/XPF/XCD are the CFA/CFP francs and the East Caribbean dollar, real currencies of ~20 countries (a test pins this). `DashboardCurrencyProvider` (rendered by BOTH the renderer and the editor) resolves one shared FX poll for the board, and frames read it through **`useMoney()`** from `@zframes/core` — `money.price(usd)` / `money.compact(usd)` take USD in and render the card's currency. The rounding kernel lives in `packages/core/src/money.ts`; `@zframes/frames`' `formatPrice`/`formatCompactUsd` delegate to it, so a dollar board and a converted board can't drift. **Symbols and minor-unit digits come from `Intl.NumberFormat`, memoized per code** — never a hand-typed table, which is what makes 146 codes maintainable and what fixed a live bug (every currency was formatted at 2 decimals, so JPY/KRW rendered a fake `¥1,234.56`; 0-minor-unit currencies now render whole, and KWD/BHD keep their third digit). Six symbol overrides survive where Intl disagrees with what market data expects (THB, SGD, CAD → `C$` not `CA$`, IDR, MYR, ZAR), and any symbol Intl returns *equal to the ISO code* gets a trailing space appended, so `CHF 20.66` is emergent rather than hand-written. `formatMagnitude` stays deliberately currency-blind — it's a *scale* (`1.23T`), so per-currency decimals there would make one board's aggregates disagree with another's. Two carve-outs: until the FX rate resolves the card keeps quoting USD (a wrong number is worse than a slow one), and **US-macro frames stay USD on purpose** (a baht-converted national debt is a figure nobody quotes). **The frame layer is fully migrated** (66 frames): every frame that renders convertible market money goes through `useMoney()`. The exemptions are explicit and enforced — `tests/currency-coverage.test.ts` fails the build if a frame outside its `USD_ONLY` list references `formatPrice`/`formatCompactUsd`, so a new frame can't quietly reintroduce a hard-coded `$`. **Two senses of "currency" coexist, at different levels of the spec:** `FrameInstance.currency` (sibling of `config`) is *display*, while the metals LBMA-fix frames' `config.currency` picks **which published fix series to read** (the LBMA fixes each metal in USD/GBP/EUR as separate prints) — a *data* choice. They never collide: different objects, and `config.currency`'s enum rejects a display code like `THB` with the valid options named, so the confusable mistake fails loudly at lint time rather than silently. Their USD series is canonical and goes through `money` (so it follows the board); a GBP/EUR series is genuinely not USD and is shown **as published**, because the display layer converts *from* USD and would otherwise multiply a sterling number by the wrong rate. Exempt by category: **US-macro** (national debt, NY Fed / Treasury rate boards, auction sizes, debt composition — nobody quotes those in baht), **SEC-filing figures as reported** (`fundamentals`, `capital-structure-bars`), and **user-entered numbers** (`breakeven`, `returns-projector`, `risk-reward`, `journal-*` — a typed value must read back as typed).
- **Event markers belong to the card, not the board.** `FrameInstance.events` (sibling of `config`, like `title`/`currency`/`style`) is a card's own list of dated annotations; there is deliberately **no** `spec.events`, because an event explains a series, not a dashboard — a board-wide list was the first cut and it put the same flag on every chart. Frames render **`TimeSeriesChart`** (`@zframes/frames`' `series-chart.tsx`), never the raw `MultiSeriesLineChart`: the wrapper injects the card's markers via `useEvents()`, and the frame's meta must set **`annotatable: true`** (what tells the editor to offer its Events panel and the AI catalogue that the frame accepts markers). `tests/chart-events-coverage.test.ts` fails the build if either half drifts — a chart that quietly opted out just looks like a card nobody annotated. Dates are parsed as **local** midnight (a bare `YYYY-MM-DD` read as UTC would draw the flag a day early west of Greenwich). Markers are authored, never fetched — no feed knows which events a chart cares about.
- **Frames nest one level, inside a container frame.** `FrameInstance.children` (sibling of `config`, like `events`/`title`/`currency`/`style`) holds the frames a **container** frame renders as its own little grid — so a cluster (a 2x2 of sparklines, a chart over its own stat strip, a split pane) occupies ONE board slot and drags/resizes as a unit instead of coming apart on every rearrange. The renderer and editor branch on `FrameMeta.container`, never on a frame name; `group` (`packages/frames`) is the only container today. A container's config supplies its inner grid's units (`columns`, `rows`, `gap`, plus `panel` for an optional surrounding surface), emitted as `--zf-sub-cols/rows/gap` — a child's placement resolves against THOSE, never the board's `--zf-cols`/`--zf-gap`, and its rows are **fractions** of the group's height (not `grid.rowHeight` px) so the cluster always fills its slot. Child spans are clamped to the group: the board grows downward, a group cannot, so an unclamped child spills out of the card. **Groups do not nest** — `ChildFrameInstanceSchema` declares `children: z.never().optional()` rather than omitting the field, because a plain `z.object` would *strip* it and a group-in-a-group would parse cleanly then render empty (the worst feedback a generating agent can get); `MAX_GROUP_CHILDREN` (24) bounds one group. Two footguns: FRAME_CSS's phone/tablet reflow rules must stay scoped to `.zf-grid > .zf-frame` (as descendant selectors they also matched a group's children and stacked them inside a slot that didn't grow), and a container renders `.zf-group` — not `.zf-frame` — so any test or host that selects cards needs that class too. In the editor the group's content box IS a nested GridStack (`grid.makeSubGrid(el, opts, undefined, false)`, with the `grid-stack` class added *first* so GridStack reuses that box instead of inserting its own wrapper); children are draggable in place and between group and board, and `collectSpec` reads them back off the live nested grid.
- **`source` pins a frame to a provider.** Capability routing is first-match (`useProviderFor(cap, source?)`), so a second provider for an existing capability is unreachable by default. Frames whose capability more than one exchange serves take an optional `source` (the shared `sourceField()` in `schemas.ts`) and pass it to their hook; an unknown source falls back to first-match rather than rendering an empty card. **Symbols are source-native** — Hyperliquid wants `BTC`/`xyz:TSLA`, Bitkub wants bare `KUB`/`BTC` and has no HIP-3 stock perps — and capabilities are source-specific too: only Hyperliquid streams `quote-stream`, so a Bitkub `price-chart` runs on polled candles with no live tick.
- **Provider caching is centralised** — every provider method that hits a free, rate-limited public API wraps its fetch in the shared `@zframes/data-primitives/cache` (`TtlCache`), never a hand-rolled `memo`/`Map`/`localStorage` cache. This covers **request/response endpoints only** — a live WebSocket stream (e.g. Hyperliquid's `allMids`) is never TTL-cached; streams are shared via one socket + last-value fan-out, with no TTL or persist. One `TtlCache` instance per logical source; a `key` distinguishes argument variants (series id, CIK, page size), a single-value source uses a constant key (`"latest"`). It gives freshness (TTL), in-flight dedup, stale-on-error, and opt-in `persist` (localStorage; browser-only, JSON-safe values only — not `Map`s) in one place. **Pick the TTL just under the hook's poll interval** so background polls still refresh while reloads/extra frames reuse the cache (e.g. CoinGecko 12 m under a 15 m poll; Treasury 3 h under a 6 h poll). Capability hooks in `packages/core/src/hooks.tsx` own the poll cadence (`usePolled`'s `refreshMs`, jittered); the provider cache owns reuse — keep the two distinct. **The cache is size-bounded** (`maxEntries`, default 24, trimmed oldest-first across BOTH the memo and the namespace's localStorage keys) because several keys embed a **drifting** value: a candle/funding key carries the caller's `startTimeMs`, which frames compute as `Date.now() - window` once per mount, so the same chart mints a fresh key on every reload. Unbounded, that grew localStorage until the ~5 MB origin quota, where `setItem` throws and the write guard swallows it — persistence silently stopping with no symptom. Prefer a key that doesn't drift where the window allows it (`options-iv` quantises its start to the resolution bucket); the cap is the backstop, not the design.
- **Editable dashboard** (`@zframes/editor/editor` → `DashboardEditor`, GridStack, mirrors Zentry's "customise mode"): the agent generates `dashboard.json` AND a human edits the *same* file — drag/resize/add/delete + a per-frame config rail, then Save. Edits round-trip the human-readable `dashboard.json` (the host's `onSave`), never a localStorage blob — the spec read/write contract lives in `@zframes/serve` (`handleSpecRead`/`handleSpecWrite`) and is used by BOTH `@zframes/vite`'s `dashboardWriteback()` (dev) and the CLI's `serve` (prod), so the round-trip is identical in both. GridStack owns each item's DOM, so frames render into per-item React roots wrapped in `FramesProvider` (shared provider instances — no duplicate WS). New-frame default config = `buildDefaultConfig(def)` (in `editor.tsx`): all-optional frames resolve from `schema.safeParse({})`, and required-field frames are seeded with schema-valid placeholders (symbol fields → a stocks-first default, required strings → readable placeholders, `.positive()` numbers → 1, min-length arrays → distinct items) so a freshly-added frame renders immediately instead of as an error card. **Footgun:** `@zframes/vite` is loaded by Vite's Node config-loader, so it imports the shared module by package subpath (`@zframes/serve`), NOT a relative `./serve` — a relative extensionless import fails under Node there.

## Scope

- Keyless by default — the published CLI and all 27 market-data providers are keyless (free public APIs, no key required). An opt-in keyed/account tier exists (`provider-binance` for a connected Binance account, `provider-wallet` for a public on-chain address) but is separate from the default keyless set and not wired into the published CLI. (29 provider packages total: 27 keyless + 2 keyed; the keyless set is composed in one place, `packages/providers-keyless`.)
- Stocks-first — equity perps via Hyperliquid HIP-3 builder dexes (`dex` param, e.g. `xyz:TSLA`), with crypto alongside.

Architecture decisions, the distribution model, and roadmap live in `docs/decisions/` (kept locally, not in the public repo).
