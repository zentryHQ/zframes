# @zframes/core

The presentation layer: it turns a validated `DashboardSpec` into rendered cards.
Depends on `@zframes/spec` and nothing else (ESLint enforces it, and `gridstack`
is banned here: it belongs to `@zframes/editor`). The root barrel also re-exports
the spec kernel for frame and app consumers, and `src/barrel-surface.test.ts`
snapshot-pins that public surface.

## What lives here

`defineFrame`/`defineFrameMeta`, registry, `DashboardSpecSchema`, `DashboardRenderer` (CSS-grid; error cards for invalid config AND missing capabilities), capability-routed multi-provider hooks, `catalogueForAI`. The card/error/chrome rendering both renderers share lives in `frame-content.tsx` (`FrameContent` + `FRAME_CSS`). Spec extras: `background` (`BackgroundSchema`) on the dashboard, **per-card event markers** (`FrameInstance.events`: `EventMarkerSchema[]` — hand-authored `{date,label,note?,color?,url?}` annotations drawn on THAT card's time axis, resolved by `FrameEventsProvider` → `useEvents()`; only frames whose meta sets `annotatable` draw them; see [../spec/AGENTS.md](../spec/AGENTS.md)), **nested frame groups** (`FrameInstance.children`: `ChildFrameInstanceSchema[]` — the frames a *container* frame holds, rendered as its own little grid so a cluster takes one board slot and moves/resizes as a unit; see [../spec/AGENTS.md](../spec/AGENTS.md)), plus four dashboard-wide cosmetic groups split by fault line — `grid` (geometry: columns/rowHeight/gap), `theme` (`ThemeSchema`: colour — accentHue + accentSat for the accent, baseHue + baseSat for the dark card-surface tint, upColor + downColor for the semantic gain/loss hex pair routed through `--zf-up`/`--zf-down`), `typography` (`TypographySchema`: fontFamily sans/mono/serif + numericStyle proportional/tabular + scale global text size, applied as the host root font-size) and `appearance` (`AppearanceSchema`: card-surface radius/borderStrength/surfaceOpacity/density/elevation), each field mapped to a `--zf-*` var read by `FRAME_CSS` (the base-surface gradient is expressed off `--zf-base-hue`/`--zf-base-sat` with lightness baked, and the family routes through the `--font-dmsans` token, so the defaults reproduce the original look to within ~1/255). Named one-click looks live in `presets.ts` (`THEME_PRESETS`, exported from `@zframes/core`) — pure data the editor's Cosmetics rail and the agent can apply, never a separate render path. Every default is a visual no-op, and a legacy `grid.radius` auto-migrates into `appearance` via a spec `preprocess`. Frame meta carries a required `category` (one of `FRAME_CATEGORIES`, an ordered `{key,label,description}` taxonomy exported from `@zframes/core` — it groups the editor palette into labelled sections and is surfaced in `catalogueForAI` so the generating agent reasons by family), optional `chrome: "bare"` (renders chrome-less — headings become zone dividers) and `layout` (`{w,h,minW,minH,maxW?,maxH?}` — the frame's **size envelope**; see [../frames/AGENTS.md](../frames/AGENTS.md)). Deep exports (`@zframes/spec/spec`, `/frame`, `/catalogue`) are React-free for tooling.

## Export surface

Opt-in subpaths back the editable dashboard + the runtime: `@zframes/editor/editor` (`DashboardEditor` — see [../editor/AGENTS.md](../editor/AGENTS.md)), `@zframes/serve` (Node-only `handleSpecRead`/`handleSpecWrite` + `handleProxy` — the spec read/write contract AND a host-allowlisted same-origin official-data proxy at `/__zframes/proxy`, all shared by the dev plugin and the CLI), `@zframes/store` (Node-only global-store layer — the XDG config home, the path-vs-name `classifyTarget`, the global-default-first `resolveServeTarget`, and `list`/`getDefault`/`setDefault`; the CLI commands + the keyed-account credential path all read the one home from here), and `@zframes/vite` (`dashboardWriteback()` dev plugin, which also serves the spec for the app to fetch).

## Frame chrome

- Frame chrome (cards, titles, hover) lives in the renderer's injected `.zf-*` stylesheet, themeable via `--zf-*` CSS vars — frames style only their interior.

## Display currency

- **Display currency is a display-layer concern, never a provider one.** Every capability is denominated in **USD** — a provider on a non-USD source converts on the way out (see `provider-bitkub`). The dashboard declares `currency: { code }` (`CurrencySchema`, **146 codes**) and a single card can override it with `FrameInstance.currency` — note the two are **different shapes**: the board field is an object (`currency: { code: "THB" }`) while the per-card override is a **bare code string** (`currency: "USD"`, a sibling of `config`). Both are settable from the editor: a searchable `CurrencyPicker` (`packages/editor/src/currency-picker.tsx`, matching on code + symbol + `Intl.DisplayNames` name, majors pinned first since 146 codes sorted alphabetically would open on AED) backs the Cosmetics rail's Currency section and a per-card "Display currency" field in the frame config rail. Picking **"Inherit board"** *deletes* the key rather than writing a value equal to the board's — a card pinned to `USD` stops following the board, so inherit and pin are genuinely different documents. the list is **derived, not hand-typed** — a code ships only if **at least two** of `provider-fx`'s four chain sources quote it, so every board currency inherits the chain's fallback rather than resting on one upstream. Deliberately excluded: single-source fiat (VES, ZWG, SLE, MRU, STN, XCG, CNH — one quoting source each), metals (XAU/XAG/XPT/XPD are *units*, not currencies), crypto, funds codes (XDR), and codes `Intl` still carries but ISO-4217 withdrew (HRK, CUC, SLL, ZWL, ANG). A weekly monitor (`.github/scripts/fx-coverage.mjs`) re-derives the ≥2-source set from live coverage and files an issue when a shipped code loses its fallback — and deliberately **skips the diff entirely** when any source is unreachable, since recomputing from the survivors would report half the enum as regressed. **Footgun:** the metals exclusion must never be a blanket `X*` filter — XAF/XOF/XPF/XCD are the CFA/CFP francs and the East Caribbean dollar, real currencies of ~20 countries (a test pins this). `DashboardCurrencyProvider` (rendered by BOTH the renderer and the editor) resolves one shared FX poll for the board, and frames read it through **`useMoney()`** from `@zframes/core` — `money.price(usd)` / `money.compact(usd)` take USD in and render the card's currency. The rounding kernel lives in `packages/core/src/money.ts`; `@zframes/frames`' `formatPrice`/`formatCompactUsd` delegate to it, so a dollar board and a converted board can't drift. **Symbols and minor-unit digits come from `Intl.NumberFormat`, memoized per code** — never a hand-typed table, which is what makes 146 codes maintainable and what fixed a live bug (every currency was formatted at 2 decimals, so JPY/KRW rendered a fake `¥1,234.56`; 0-minor-unit currencies now render whole, and KWD/BHD keep their third digit). Six symbol overrides survive where Intl disagrees with what market data expects (THB, SGD, CAD → `C$` not `CA$`, IDR, MYR, ZAR), and any symbol Intl returns *equal to the ISO code* gets a trailing space appended, so `CHF 20.66` is emergent rather than hand-written. `formatMagnitude` stays deliberately currency-blind — it's a *scale* (`1.23T`), so per-currency decimals there would make one board's aggregates disagree with another's. Two carve-outs: until the FX rate resolves the card keeps quoting USD (a wrong number is worse than a slow one), and **US-macro frames stay USD on purpose** (a baht-converted national debt is a figure nobody quotes). **The frame layer is fully migrated** (105 frames call `useMoney()` as of 2026-08-22): every frame that renders convertible market money goes through `useMoney()`. The exemptions are explicit, enforced, and **shipped metadata rather than a test-local list**: a frame opts out with `usdOnly: true` in its meta (16 frames today, each carrying its reason inline). That flag is what lets the editor disable the card's "Display currency" control *and say why*, and what the AI catalogue surfaces; the earlier design kept the list only in the test, so the shipped code had no idea which frames ignore the display currency and the editor offered a control a dozen cards silently dropped. `tests/currency-coverage.test.ts` now *derives* its exemptions from the flag and fails the build if any other frame references `formatPrice`/`formatCompactUsd`, so a new frame can't quietly reintroduce a hard-coded `$` and the flag can't drift from the code in either direction. **Two senses of "currency" coexist, at different levels of the spec:** `FrameInstance.currency` (sibling of `config`) is *display*, while the metals LBMA-fix frames' `config.currency` picks **which published fix series to read** (the LBMA fixes each metal in USD/GBP/EUR as separate prints) — a *data* choice. They never collide: different objects, and `config.currency`'s enum rejects a display code like `THB` with the valid options named, so the confusable mistake fails loudly at lint time rather than silently. Their USD series is canonical and goes through `money` (so it follows the board); a GBP/EUR series is genuinely not USD and is shown **as published**, because the display layer converts *from* USD and would otherwise multiply a sterling number by the wrong rate. Exempt by category: **US-macro** (national debt, NY Fed / Treasury rate boards, auction sizes, debt composition — nobody quotes those in baht), **SEC-filing figures as reported** (`fundamentals`, `capital-structure-bars`), and **user-entered numbers** (`breakeven`, `returns-projector`, `risk-reward`, `journal-*` — a typed value must read back as typed).
