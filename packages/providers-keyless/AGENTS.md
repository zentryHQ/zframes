# Market-data providers

`@zframes/providers-keyless` is the composition leaf that assembles the keyless
fleet for the hosts. **It is the source of truth for which providers ship**, so
trust that file over any count written in prose.

Every provider is a React-free data adapter over `@zframes/spec` +
`@zframes/data-primitives` and may import nothing else (ESLint + `tests/dep-dag.test.ts`
both enforce it). Adding one: a new `packages/provider-*`, then wiring in the
composition roots (`apps/runtime/src/App.tsx`, explorer) and in this package.

## Two conventions that apply to every provider

### Caching

- **Provider caching is centralised** — every provider method that hits a free, rate-limited public API wraps its fetch in the shared `@zframes/data-primitives/cache` (`TtlCache`), never a hand-rolled `memo`/`Map`/`localStorage` cache. This covers **request/response endpoints only** — a live WebSocket stream (e.g. Hyperliquid's `allMids`) is never TTL-cached; streams are shared via one socket + last-value fan-out, with no TTL or persist. One `TtlCache` instance per logical source; a `key` distinguishes argument variants (series id, CIK, page size), a single-value source uses a constant key (`"latest"`). It gives freshness (TTL), in-flight dedup, stale-on-error, and opt-in `persist` (localStorage; browser-only, JSON-safe values only — not `Map`s) in one place. **Pick the TTL just under the hook's poll interval** so background polls still refresh while reloads/extra frames reuse the cache (e.g. CoinGecko 12 m under a 15 m poll; Treasury 3 h under a 6 h poll). Capability hooks in `packages/core/src/hooks.tsx` own the poll cadence (`usePolled`'s `refreshMs`, jittered); the provider cache owns reuse — keep the two distinct. **The cache is size-bounded** (`maxEntries`, default 24, trimmed oldest-first across BOTH the memo and the namespace's localStorage keys) because several keys embed a **drifting** value: a candle/funding key carries the caller's `startTimeMs`, which frames compute as `Date.now() - window` once per mount, so the same chart mints a fresh key on every reload. Unbounded, that grew localStorage until the ~5 MB origin quota, where `setItem` throws and the write guard swallows it — persistence silently stopping with no symptom. Prefer a key that doesn't drift where the window allows it (`options-iv` quantises its start to the resolution bucket); the cap is the backstop, not the design.

### Pinning a frame to a provider

- **`source` pins a frame to a provider.** Capability routing is first-match (`useProviderFor(cap, source?)`), so a second provider for an existing capability is unreachable by default. Frames whose capability more than one exchange serves take an optional `source` (the shared `sourceField()` in `schemas.ts`) and pass it to their hook; an unknown source falls back to first-match rather than rendering an empty card. **Symbols are source-native** — Hyperliquid wants `BTC`/`xyz:TSLA`, Bitkub wants bare `KUB`/`BTC` and has no HIP-3 stock perps — and capabilities are source-specific too: only Hyperliquid streams `quote-stream`, so a Bitkub `price-chart` runs on polled candles with no live tick.

## Shared primitives

Provider primitives, React-free and used by every provider: `@zframes/data-primitives/fetch` (the shared transport — UA, proxy rewrite, abort, optional Zod validation), `@zframes/data-primitives/cache` (`TtlCache` — the shared TTL + in-flight-dedup + stale-on-error + opt-in-persist cache; see **Caching** above) and `@zframes/data-primitives/csv` (`splitCsvRow`/`parseCsvRows` — quote-aware row parsing for the CSV-published official sources; a bare `split(",")` is silently wrong on any file whose rows quote a comma, e.g. Zillow's `"Austin, TX"`, and shifts every later column by one).

## Official-data proxy

**Official-data proxy:** browsers can't fetch CORS-blocked official sources (SEC XBRL, H.15, OFR, halts), so a provider passes `fetchJson(url, schema, { proxied: true })` — in the browser this rewrites to the same-origin `/__zframes/proxy?url=…` route (Node relays it; allowlisted hosts only, https/GET-only, browser UA or `--contact`/`ZFRAMES_CONTACT`); in Node it's a no-op (no CORS there). Proxied frames degrade to empty on a static host with no runtime. See the proxy decision in `docs/decisions/providers/providers.md`.

A new proxied host must be added to the allowlist in `packages/serve/src/serve.ts`,
or the relay refuses it.

## The fleet

- **Crypto market data (keyless):**
  - `packages/provider-hyperliquid` — free no-key provider: allMids WS (one subscription per HIP-3 dex, added lazily from requested symbols), day stats per dex (full default-dex universe when no symbols given; a `"<dex>:*"` wildcard symbol — e.g. `"xyz:*"` — returns that dex's *entire* universe, used by the ticker tape to surface every HIP-3 equity), fundingHistory, candleSnapshot, open interest (`open-interest` capability — live single-venue notional, read from the same `metaAndAssetCtxs` call as day stats; no history endpoint)
  - `packages/provider-coingecko` — global marketcap + dominance (`global-market`), per-coin market caps (`coin-markets`, top-50 by mcap with 24h change), trending coins (`trending-coins`), sector performance (`sector-performance`), and blue-chip NFT collections (`nft-market` — floor/24h-change/volume/sales for ~10 curated slugs, fetched **sequentially** one `/nfts/{id}` call at a time with per-collection skip-on-fail and a long 45 m TTL, since the keyless tier has no bulk NFT endpoint and shares this provider's rate limit); plus a per-asset research profile (`crypto-profile` — identity, categories, links, market-cap rank, ATH/ATL with dates, the circulating/total/max supply triple, FDV and public-repo dev activity, from one `/coins/{id}` call). **Frames hold tickers but this API is keyed by CoinGecko id**, so the provider resolves `BTC` → `bitcoin` itself via `/search` (exact-symbol match, lowest `market_cap_rank` wins — many junk tokens claim a major's ticker) behind its own long-TTL cache, with a hardcoded majors fast path. `max_supply: null` maps to **absent, never 0** — a 0 cap would render as "fully diluted", the opposite of the truth. free tier no key, all endpoints cached behind `TtlCache` (stale-on-429)
  - `packages/provider-coinpaprika` — broad multi-window coin movers across ~2000 coins (`coin-movers` capability)
  - `packages/provider-alternativeme` — fear & greed index (`sentiment` capability)
  - `packages/provider-etf-flows`: US spot Bitcoin/Ethereum ETF flows (`etf-flows`), daily total net-inflow history plus a per-issuer snapshot (ticker, daily net, net assets, cumulative net), keyed `btc`/`eth`. Keyless and CORS-open via SoSoValue's public gateway (`api.sosovalue.xyz`), two POSTs per asset, 6h TTL since the underlying data is daily. **Best-effort by design:** this is SoSoValue's undocumented internal gateway (the documented API is key-gated), so a failed fetch throws and the cache serves last-good rather than blanking the card. Every number arrives nested as `{value}` and has to be read through it.
  - `packages/provider-polymarket`: prediction-market odds (`prediction-markets`) from Polymarket's public Gamma API (`gamma-api.polymarket.com`), keyless and CORS-open, no proxy. Returns the highest-volume open markets with each outcome's market-implied probability. **Footgun:** Gamma encodes `outcomes` and `outcomePrices` as JSON-stringified arrays that must be parsed and paired positionally, and a price is a 0-to-1 probability, not a dollar amount. Cloudflare-cached ~5 min, so a 4 min TTL.
- **On-chain / DeFi (keyless):**
  - `packages/provider-defillama` — keyless via api.llama.fi (CORS-open): TVL per chain (`tvl`), DEX volume (`dex-volume`, snapshot + per-protocol history), protocol TVL (`protocol-tvl`, snapshot + per-protocol history), protocol fees (`protocol-fees`), one protocol's fee **and revenue** history (`protocol-fundamentals` — the crypto income statement), and its emission schedule (`token-unlocks`). Snapshots/histories cached behind `@zframes/data-primitives/cache`'s `TtlCache`. **Three footguns.** `summary/fees/{slug}` returns ONE series per call and `dataType` swaps *which metric fills identical keys*, so fees and revenue are indistinguishable by shape and need **two** calls; `excludeTotalDataChartBreakdown=true` is mandatory, not an optimisation (30 KB with it, 714 KB without); and `totalDataChart` timestamps are unix **seconds**. `fees` is what users paid, `revenue` only what the protocol kept — a P/S analogue must use revenue, or a pass-through DEX looks 28× cheaper than it is. Slug ≠ ticker and the mapping is unreliable (`lido`, not the CoinGecko id `lido-dao`; `arbitrum` and `arbitrum-foundation` both resolve and report **different** revenue), so both capabilities stay slug-keyed. Unlocks are the one **forward-looking** supply source in the fleet: `api.llama.fi/emissions` is HTTP **402** (paid), but the frontend dataset host `defillama-datasets.llama.fi` is open and CORS-clean
  - `packages/provider-mempool` — Bitcoin fees, mempool, blocks, hashrate, difficulty, mining pools, and Lightning stats (keyless, mempool.space)
  - `packages/provider-geckoterminal` — trending/hot DEX pools per network (`dex-pools`) via GeckoTerminal's keyless public API (~30 req/min): pair, base-token price, 24h volume/change, liquidity, trade count; keyed by network (eth/solana/base/…), short TTL (not persisted — hot pools are too short-lived)
  - `packages/provider-blockchair` — cross-chain network activity (`chain-activity`) for major L1s (Bitcoin, Ethereum, Litecoin, Dogecoin, …) via Blockchair's keyless `/{chain}/stats`: 24h tx count, blocks, mempool size, native price + 24h change; per-chain calls fan out in parallel with skip-on-fail, aggregate cached 4 m
  - `packages/provider-coinmetrics`: the deep on-chain valuation base (`onchain-valuation` + `price-history-daily`) from the Coin Metrics community API (`community-api.coinmetrics.io`), keyless and CORS-open. ONE full-history daily request (~5.8k rows for BTC, no pagination in practice) feeds both capabilities off a shared asset-keyed cache, so a valuation card and a cycle-multiple card on the same board dedup to a single fetch. **Footgun:** realized cap (`CapRealUSD`) is a PAID metric, so realized cap and realized price are *derived* from the community tier's MVRV and supply (`realizedCap = marketCap / MVRV`), which is why the request asks for exactly `PriceUSD,CapMrktCurUSD,SplyCur,CapMVRVCur`. 3h TTL, deliberately not persisted (the full-history payload is large and a reload at this cadence is cheap).
  - `packages/provider-bitcoin-data`: Bitcoin cycle oscillators (`onchain-cycle-extras`: SOPR, Puell multiple, reserve risk) from bitcoin-data.com, keyless and CORS-open. **Its free tier is hard-capped at 10 requests/hour**, so all three series load behind ONE shared long-TTL poll (3 requests per refresh, 18h cache, in-flight dedup, stale-on-429), and a frame must not poll it faster than its 12h+ hook. **Footgun:** the value field is named per endpoint (`sopr`, `puellMultiple`, `reserveRisk`), so rows are read generically (the first field that is neither `d` nor `unixTs` and parses finite), which is what stops an upstream slug rename from silently zeroing a series.
  - `packages/provider-ultrasound`: Ethereum supply economics (`eth-supply`) from ultrasound.money's public v2 API, keyless and CORS-open, the ETH counterpart to `provider-mempool`. One `getEthSupply` fans four endpoints (burn/issuance gauges, validator APR, per-minute burn, supply history) behind a single cache; the gauge-rates leg is load-bearing (without it the reading is meaningless, so it throws and the cache serves last-good) while the other three degrade individually. Cloudflare-fronted with ~6s max-age, polled gently at a 2 min TTL.
- **Non-USD source (keyless):**
  - `packages/provider-bitkub` — Bitkub, Thailand's largest exchange and where KUB actually trades. Fulfils the SAME capabilities the other sources do (`day-stats`, `ohlcv`, plus `order-book`, which no other provider has), so **existing** frames render it — a frame reaches it by pinning `source: "bitkub"` in its config, since capability routing is otherwise first-match. Bitkub quotes in THB but every capability is denominated in USD, so prices are converted on the way out at the live USD/THB rate (fetched by the provider itself — the layer DAG forbids importing `provider-fx` — through its own copy of the same four-source chain, 1 h TTL, persisted); sizes/volumes in the base asset are NOT converted. **Every rate is sanity-checked before dividing by it** (`10 ≤ USD/THB ≤ 100`, falling through to the next source otherwise), because a wrong-but-finite rate corrupts every price here more quietly than an outage does; when the whole chain is down a stale cached rate is served rather than throwing. **Footgun:** v1 and v3 spell pairs differently and are not interchangeable — v1's ticker map keys are quote-first (`THB_KUB`), while v3/chart endpoints want base-first (`KUB_THB`), and `/api/market/depth?sym=THB_KUB` answers HTTP 200 with a *different pair's* book instead of an error. The chart endpoint also rejects TradingView's `countback`, so the candle window is anchored to `Date.now()` per call.
- **Derivatives / options (keyless):**
  - `packages/provider-deribit` — BTC/ETH put-call ratio, OI-by-strike, DVOL volatility index, plus the full per-contract chain (`options-chain`, the asset-class-agnostic shape equities and metal ETFs also fill) (Deribit public API, no key). **Two books:** BTC and ETH have deep **inverse** (coin-margined) books of their own, while every other underlying is a **linear** USDC option and they all arrive in ONE combined `currency=USDC` call — `currency=SOL` is not an error, it answers 200 with an empty book, so a per-currency call would report SOL as unlisted when 560 contracts exist. **Unit traps, all live-confirmed:** the inverse book quotes premiums in the BASE COIN (a real row's `bid_price` 0.642 is ≈$41.5k, not $0.64 — it must be multiplied by the index), `underlying_price` is the per-expiry FORWARD (it ranged 64,592→67,105 inside one payload) so chain-level spot comes from `estimated_delivery_price`, OI/volume are in the base coin not 100-share lots, `mark_iv` is PERCENT while `OptionContract.iv` is a DECIMAL, and sub-dollar linear strikes are spelled `0d24` (= 0.24). **No greeks** — they exist only on the per-instrument `ticker` call, i.e. 834 requests for one BTC chain, so they stay `undefined` and a frame hides those columns
  - `packages/provider-cboe`: delayed listed-equity option chains (`options-chain`), the equity counterpart to Deribit's crypto books, and the one source in the fleet that ships full greeks. `cdn.cboe.com/api/global/delayed_quotes/options/<SYMBOL>.json` is what Cboe's own public quote pages read: no key, no token, no signup, and it answers the WHOLE chain for an underlying in one document (every listed expiry, both sides, with IV, greeks, open interest and volume per contract). Quotes lag **15 minutes**, reported in `OptionsChain.delayMinutes` rather than buried, so a frame can label it honestly. Proxied (the CDN sends no `Access-Control-Allow-Origin`; `cdn.cboe.com` is on the serve allowlist), so it degrades to empty on a static host. **Three footguns.** Expiry, strike and side exist NOWHERE except inside the OCC-21 `option` id, so `occ.ts` parses every row and parses it **from the right**: the 15 trailing characters are fixed-width but the root runs 1 to 6 characters and may carry digits on adjusted series, so a left-to-right parse assuming a four-letter root reads Ford's date field out of its strike and yields a plausible-looking wrong contract. The CDN keys are case-sensitive object names (`nvda.json` is a 403, not a redirect to the uppercase one). And one chain is ~1.7 MB of JSON (~3,900 contracts for a name like NVDA), so `persist: false` is mandatory rather than tidy: two or three underlyings exhaust the ~5 MB origin quota, at which point `setItem` throws, the cache swallows it, and persistence stops silently for EVERY other provider on the board.
- **FX (keyless):**
  - `packages/provider-fx` — foreign-exchange reference rates with a short trend (`fx-rates` + `dollar-index` capabilities), resolved through an **ordered chain of four keyless CORS-open upstreams** (`sources.ts`): Frankfurter/ECB (primary — the healthy path still makes exactly one request) → FXRatesAPI → currency-api (pages.dev, CC0) → ECB Data Portal direct (SDMX). Each adapter normalizes into one internal `RateTable`, so the chain is invisible to callers; when all four fail the **primary's** error is re-thrown. A 429 both falls through **and** cools that source down for 10 min. Opt-in `{ intraday: true }` attaches FXRatesAPI's minute quote as `spot`/`spotAt` and deliberately leaves `rate`/`history`/`changePct` on the published daily close — the board's conversion rate must not flap between polls. History depth is per-call (`{ windowDays }`, default `FX_DEFAULT_WINDOW_DAYS = 40`; the deep sources reach 1999) and is part of the cache key. **Footgun:** FXRatesAPI serves timeseries **newest-first**, and the ECB portal sends `structure.dimensions` (plural), not the documented `dimension`.
- **Metals / commodities (keyless):**
  - `packages/provider-metals` — gold, silver, platinum, palladium and copper from four keyless sources: live spot via gold-api.com (`metal-spot`), the LBMA's own daily London fix files back to **1968** (`metal-history` — the deepest price history in the fleet; ~150 KB gzipped per metal, so its `TtlCache` is 6h and deliberately **not** persisted), the CFTC's public Socrata Commitments-of-Traders dataset (`metal-positioning`, weekly), the U.S. Treasury's monthly official gold-reserve report (`gold-reserve`, the one proxied call — fiscaldata is already allowlisted), gold-backed tokens via CoinGecko (`tokenized-gold`, premium vs spot), and Cboe's published commodity implied-vol indices (`commodity-vol-index` — GVZ gold / VXSLV silver / VXGDX miners / OVX oil, the metals counterpart of the VIX; proxied CSV, ~90–160 KB). `metal-positioning` now merges the CFTC's **disaggregated** report (`72hh-3qpy`) onto the legacy weeks as `CotWeek.disaggregated`, splitting producer-merchant hedging from swap-dealer bank shorts and adding trader counts and 4-/8-trader concentration — the legacy `commercial` bucket conflates the two, which is the most common misreading of gold positioning. **Three footguns:** CFTC spells `swap__positions_short_all` and `swap__positions_spread_all` with a DOUBLE underscore while `swap_positions_long_all` has one (a single-underscore guess silently reads 0 where gold's real bank short is 215k contracts); the Cboe CSV header shape differs per index (`GVZ`/`OVX` are close-only, `VXSLV`/`VXGDX` are OHLC), so the close column must be located by NAME or a positional parser publishes each day's open as its close; and OVX's published file starts 2009-09-18, not at the index's 2007 launch. Spot change is measured against the latest London fix: the history warm-up is fire-and-forget, so the change appears a poll after the price rather than blocking first paint on a decades-deep download.
- **Official US macro & financial data (keyless, same-origin proxy required — these degrade to empty on a static host):**
  - `packages/provider-treasury` — U.S. Treasury data: average interest rates, debt-to-penny, completed auctions, and the daily yield curve (fiscaldata + home.treasury.gov, both proxied)
  - `packages/provider-nyfed` — New York Fed reference rates (SOFR, EFFR, repo)
  - `packages/provider-ofr` — OFR Financial Stress Index (`financial-stress` capability)
  - `packages/provider-bls` — BLS public time series (CPI, unemployment, etc.)
  - `packages/provider-finra` — FINRA daily reported short-sale volume (`short-volume`; cdn.finra.org is CORS-blocked in the browser, so it routes through the proxy)
  - `packages/provider-sec` — SEC EDGAR company filings + XBRL financials, snapshot (`fundamentals`) and full reported history (`fundamentals-history`, merged across the tag aliases an issuer switches between mid-history — NVDA's revenue stops at FY2022 on any single tag). **Both endpoints route through the proxy**: `data.sec.gov/submissions` answers `access-control-allow-origin: *` to curl but its direct browser fetch never resolves (verified 2026-08-06) — the same trap fiscaldata set, so never conclude a host is browser-reachable from a curl header
  - `packages/provider-news` — news-outlet headlines via RSS (`news` capability)
  - `packages/provider-fred` — FRED (St. Louis Fed) published series, ONE provider parameterised by series id (the provider-metals pattern) across four capabilities: `index-level` (SP500 / VIXCLS / NASDAQCOM), `credit-spread` (the ICE BofA high-yield + investment-grade OAS pair), `housing-price` (Case-Shiller national) `mortgage-rate` (the Freddie Mac 30y benchmark, which FRED mirrors — so no separate PMMS provider), and `macro-reference-series` (the macro backdrop a commodity is read against: `CPIAUCSL` CPI back to **1947**, `DFII10` 10y TIPS real yield, `REAINTRATREARAT10Y` 10y real rate back to 1982, `DTWEXBGS` broad dollar, `T10YIE` breakeven). **That last name is load-bearing:** `macro-series` was already taken by `provider-bls` (period-labelled CPI/unemployment), which sits EARLIER in the keyless routing order, and routing is first-match — so reusing it would have handed every FRED id to BLS, and reordering would have broken the six BLS frames instead. No registration order makes both work. **Keyless because it reads `fredgraph.csv?id=…`** — the endpoint FRED's own charts download — not the key-gated `api.stlouisfed.org`. Two footguns: `id=A,B` fetches several series in **one** call on a shared date grid (how the spread pair stays aligned by construction), and FRED's **licensed series carry a rolling window** — `SP500` is ~10 years and the BAML spreads ~3, while NASDAQCOM/MORTGAGE30US (1971) and CSUSHPINSA (1987) are deep, so a 20-year request on the S&P returns the 10 that exist.
  - `packages/provider-fhfa` — FHFA House Price Index at **state and metro** granularity, quarterly back to 1975 (`regional-housing-price`) — the sub-national counterpart to FRED's single national series. **Footgun cluster, all confirmed live:** the combined `hpi_master.csv` is ~17 MB, *over* `PROXY_MAX_BYTES`, so it relays as a 502 "upstream response too large" while `curl` looks fine — this reads the small per-level files instead (`hpi_at_state.csv` ~190 KB, `hpi_at_metro.csv` ~4 MB); filenames are **lowercase** (`HPI_master.csv` 404s); the `hpi_po_*.csv` "purchase-only" files are actually **XLSX** behind a `.csv` name; the files have **no header row** and their column order DIFFERS by level; and the metro change column uses undocumented accounting parentheses (`( 3.62)`), so year-over-year is computed from the index instead. Metro keys are full CBSA titles, so a leading fragment resolves case-insensitively ("Austin" → "Austin-Round Rock-San Marcos, TX").
- **Equities (keyless, same-origin proxy required, degrades to empty on a static host):**
  - `packages/provider-nasdaq`: the equity deep-dive source, **eight capabilities off one host** (`day-stats`, `ohlcv`, `equity-profile`, `equity-financials`, `earnings-history`, `earnings-calendar`, `analyst-ratings`, `institutional-ownership`). `api.nasdaq.com` is what nasdaq.com's own quote pages call: no key, no token, no signup, and it is the only free source in the fleet publishing all of a consolidated listed quote, decades of daily bars, pre-aligned multi-year financial statements, a reported-vs-consensus earnings record, a market-wide earnings calendar, sell-side consensus, and 13F ownership aggregates. **Every call passes `proxied: true`** (the host sends no `Access-Control-Allow-Origin` at all, and the proxy's desktop-Chrome UA is also what makes these endpoints answer). **It is an internal site API and is treated as one:** undocumented, unversioned, no stability contract, so three things are the design of the file rather than an afterthought. Every method fails LOUDLY (an envelope reporting failure, or a payload yielding nothing parseable, throws with the upstream message instead of returning a half-parsed object). Every read has stale-on-error, so a transient block serves last-good rather than blanking a card. And every coercion in `parse.ts` returns `null` for an unreadable cell, so a shape change surfaces as a missing field or a gap in a series, never as a `NaN` and never as a `0` that would draw a real trough where there is only a missing print. **Two live-confirmed quirks:** the summary endpoint misspells its 52-week key as `FiftTwoWeekHighLow`, and the statement tables are denominated in thousands while the ratios table beside them is not.
- **Housing (keyless, NO proxy — CORS-open):**
  - `packages/provider-zillow` — the Zillow Home Value Index (`home-value-index`): the typical home value per US metro in **dollars**, not index points, monthly back to 2000. The only house-price source in the fleet denominated in money, so it answers "what would a house cost there" rather than "how much have prices risen" — and therefore the only one that goes through `useMoney()` while the index series stay unit-less. `files.zillowstatic.com` sends `Access-Control-Allow-Origin: *`, so it fetches direct and keeps working on a static host. One wide table (~895 rows × ~318 month columns, ~4.4 MB), so the cache holds the parsed **table** under a constant key and slices per request — a board with three ZHVI cards costs one download, not three.
- **Keyed / account tier (opt-in, not in the published keyless CLI by default):**
  - `packages/provider-binance` — connected Binance account (`portfolio` capability); secret never reaches the browser — routed through the runtime's server-side signed relay
  - `packages/provider-wallet` — public on-chain wallet address (`portfolio` capability); Ethereum balances via public RPC + bundled token list, priced through CoinGecko; no key, no relay

## Cross-asset deep dive

**Cross-asset deep dive.** A stocks-first board gets a company-research surface; the same question is asked of the other asset classes through six capabilities, all keyless and all on EXISTING provider packages (no new provider, so `providers-keyless` is untouched): crypto gets `crypto-profile` (identity + the supply triple, since a token has no filings and dilution is the whole investment case), `protocol-fundamentals` (fees vs revenue — the crypto income statement) and `token-unlocks` (the only forward-looking supply data in the fleet, the analogue of a share-lockup expiry); commodities get `commodity-vol-index` (a metal has no earnings, so its own implied-vol regime is how "expensive" is answered) and `macro-reference-series` (CPI-deflated real price — for gold, the real 1980 peak IS its valuation history); and `options-chain` is deliberately asset-class-agnostic, so one frame reads a crypto venue, a listed equity and a metal ETF alike, pinned with `source`. **Metal option chains need no work of their own** — `cdn.cboe.com` serves GLD/SLV/IAU/PPLT/CPER with full greeks through the same capability. **Every direct physical-gold source is a dead end** (SPDR's "CSV" is a PDF, iShares serves a bot-wall as `text/csv`, CME 403s, WGC has no API, IMF's data host no longer resolves) — don't budget for real vault or central-bank tonnage.
